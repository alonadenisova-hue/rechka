# ИИ‑Шарик — очередь задач

Как пользоваться: берите **первую невыполненную** задачу, открывайте **новый чат** (облако, репозиторий `rechka`)
и вставляйте текст из блока целиком. Одна задача — один чат. С версии 36 код приложения
разделён на файлы `app/js/*.js`: задачи, которые меняют разные файлы, можно делать параллельно (пометка «🟢 можно параллельно»);
номер версии и `app/sw.js` при этом правит тот чат, который сливает PR последним.

Каждый чат в конце сам: проверяет (как написано в `CLAUDE.md`), сливает PR в `main`, отмечает задачу здесь ✅
и присылает архив `app/` для сайта.

Общий контекст для всех задач уже в репозитории: `CLAUDE.md`, `docs/ai-sharik/README.md`, `docs/ai-sharik/TASKS.md`,
`cloud/sharik/README.md`.

- «Где у Шарика нос?» — нажать на самого героя (ухо, хвост, нос, лапа, глаз, рот, живот); «Это мой нос.»;
- «Дай Шарику рыбу!» — выбрать предмет, он ест или играет: «Я ем рыбу.», «Я играю!»;
- «Посади Шарика на стол / под стол!» (со 2 уровня) — предлоги действием: «Шарик на столе.»;
- «Позови Шарика!» (он спит вдалеке — голос будит, и он прибегает) и «Скажи как Шарик: мяу!» — любой звук засчитан,
  всегда есть кнопка мамы.

## 11. Одно хорошее пятиминутное занятие (план после разбора 13 ноября) — СЛЕДУЮЩАЯ ЗАДАЧА
Разбор репозитория сторонним помощником (Codex, по версии 45) и проба дома сошлись: возможностей много, а поведение
внимательного преподавателя не доведено. Новых игр, героев и функций пока не добавляем. Цель — одно занятие на 5 минут
из трёх упражнений, которое удобнее и интереснее обычного набора игр и требует меньше ручного управления.
Если получится — расширять этот способ; если нет — разбирать конкретные провалы.

Что в разборе верно и подтверждено кодом:
1. Модель не управляет самим упражнением: может выбрать игру и уровень, но не «повтори именно нос», «подожди ещё»,
   «убери один вариант», «покажи образец». Промптом это не лечится.
2. Ложная похвала: ход «А у тебя где нос?» (`shTalk`, ветка `pose`) через 3,5 с хвалит, ничего не проверив.
   Камера «Зеркала» это умеет, но к ходу не подключена.
3. Ответы ИИ теряются: приложение ждёт 2,5 с (после двух опозданий — 0,7 с), сервер — до 6,5 с. Причина запасного
   ответа (`no_key`, `timeout`, `api_…`) родителю не видна — занятие идёт, а ИИ может не участвовать.
4. Голос неоднородный: фразы игр звучат выбранным голосом, только если уже записаны на телефоне, иначе голос телефона.
   Слушание — окнами по 3 с; перебить героя нельзя.
5. Кнопка «Дальше» (задержаться на картинке) выключена в коде (`nextGate`, `if(true||…)`) — выяснить у мамы, нужна ли.
6. Тесты проверяют механизмы на подставных ответах, а не то, успел ли Лев ответить и заметил ли герой попытку.

Что уже частично закрыто версией 46 (сделана после разбора): появились задания, где герой сам упражнение
(«Играем с Шариком»), — в них ответ всегда проверяется нажатием, голосом или кнопкой мамы.

```
Задача из docs/ai-sharik/ROADMAP.md, пункт 11. Прочитай CLAUDE.md, docs/ai-sharik/README.md, этот пункт целиком,
app/js/6-sharik.js, app/js/hero-games.js, app/js/5-mirror.js, cloud/sharik/src/. Новых игр и героев НЕ добавлять.
Сделай одно пятиминутное занятие из трёх упражнений: выбор картинки («Что делает Шарик?»), попытка голоса
(«Позови Шарика»), простой жест через камеру («А у тебя где нос?» / улыбка из «Зеркала»).

Шаг 1. Единое управление занятием (на телефоне, без ожидания сервера). Каждое упражнение — явные этапы:
  показать → объяснить → ждать → заметить попытку → помочь → продолжить. Один объект состояния, один журнал событий.
  Никакой похвалы без события: нажатие, голос, жест с камеры или кнопка мамы. Нет события — герой помогает
  (повторяет, показывает сам, упрощает), а не хвалит. Убрать ложную похвалу в shTalk (ветка pose): подключить
  проверку жеста из «Зеркала» (mirrHit) и кнопку «Получилось» для мамы.
Шаг 2. Управление конкретным заданием. Игра принимает параметры: какой предмет, сколько вариантов, сколько ждать,
  какая подсказка. Действия ведущего: повторить тот же предмет, дать ещё времени, показать образец, убрать вариант,
  упростить, перейти дальше. Сначала правила на телефоне (ошибка → тот же предмет с подсказкой; успех → следующий).
  Сервер получает список разрешённых действий и может выбрать одно (поле next.action) — код проверяет и выполняет.
Шаг 3. Согласованные голос и слушание. Перед занятием заранее загрузить голос всех фраз этого занятия (их мало) —
  один голос на всё занятие; спросить маму о стоимости, если фраз больше сотни. События «герой начал говорить»,
  «Лев начал отвечать», «жест найден», «не уверен» идут в тот же журнал; если Лев подал голос во время реплики —
  герой замолкает и слушает. Ожидание ответа — настраиваемое (по умолчанию 5 с, не 3).
Шаг 4. Видимость и измерение. В «Для взрослых» после занятия — простой отчёт: сколько реплик пришло от ИИ, сколько
  запасных и почему (нет ключа, не успел, ошибка), задержки, сколько раз мама нажимала «Получилось» или «Дальше»,
  сколько попыток голоса и жестов замечено. Значок на экране занятия, когда ИИ не отвечает. Сроки ожидания
  согласовать: приложение не должно сдаваться раньше, чем сервер успевает ответить (или сервер должен отвечать быстрее).
Шаг 5. Спросить маму про кнопку «Дальше» (nextGate) и про распознавание выбора из двух слов (не для оценки).

Каждое новое поведение — с выключателем. Проверки по CLAUDE.md (audit ui, test.py nomic), тесты cloud/sharik,
npm run bundle. В отчёте честно: что проверено в браузере, а что нужно проверить на телефоне со Львом.
После этой задачи — проба дома по шагу 4; дальнейший план решать по её цифрам.
```

Не берём сейчас: готовые голосовые платформы (LiveKit и подобные) — они дают перебивание и определение конца реплики,
но это отдельный сервер, новые расходы и переделка приложения; вернуться к ним, если шаг 3 своими силами не даст
